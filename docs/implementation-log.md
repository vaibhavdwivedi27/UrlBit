## Milestone BE2 — Core URL APIs, data integrity and concurrency
- **Date:** 2026-10-23
- **Status:** Completed
- **Features completed:**
  - Domain models and JPA repositories: `ShortUrl`, `GuestQuota`, `User` (no Lombok, records for DTOs).
  - 7-character random Base62 code generator (`Base62CodeGenerator`) with `SecureRandom` and bounded collision retry.
  - Native PostgreSQL `INSERT ... ON CONFLICT (code) DO NOTHING RETURNING id` avoiding transaction aborts on code collisions.
  - Case-insensitive reserved route validator (`ReservedPathValidator`) blocking routes like `api`, `login`, `dashboard`, `actuator`.
  - Destination safety validator (`DestinationSafetyValidator`) with host normalization (case, trailing dot, IDN Punycode), loopback/private IP literal rejection, self-domain loop protection (`urlbit.in` + subdomains), and denylist checking.
  - HttpOnly guest cookie handling (`GuestCookieUtil`) with fixed 30-day non-sliding `Max-Age` and SHA-256 guest hashing.
  - Transactional guest quota counter (`guest_quotas`) atomically incremented up to 5 links; 6th request rejected with 429 (`ProblemType.GUEST_QUOTA_EXCEEDED`).
  - Single-instance in-memory IP rate limiter (`IpRateLimiter`) keyed by IPv4 address and IPv6 `/64` prefix.
  - Scheduled guest quota purge job (`GuestQuotaPurgeJob`) cleaning up records older than the 30-day cookie lifetime.
  - Public redirect endpoint `GET /{code}` returning HTTP 302 Found for active links, and uniform HTTP 404 for unknown, disabled, deleted, and expired codes (D-04).
  - Management endpoints under `/api/v1/urls`: `POST` (create), `GET /{id}` (detail), `GET` (paginated list), `PATCH /{id}` (update), `DELETE /{id}` (soft-delete).
  - Operator abuse takedown CLI (`TakedownCli`) disabling links with `disabled_reason = 'ABUSE_TAKEDOWN'`, and `PATCH` check preventing owners from re-enabling them.

## Milestone BE3 — Authentication, authorization and abuse baseline
- **Date:** 2026-10-24
- **Status:** Completed
- **Features completed:**

  - Rotating opaque refresh tokens stored only as SHA-256 hashes in `refresh_tokens`.

## Milestone BE4 — Redis caching and performance
- **Date:** 2026-10-24
- **Status:** Completed
- **Features completed:**
  - Integrated `spring-boot-starter-data-redis` with Lettuce connection pool and bounded timeouts (250ms command timeout).
  - Cache-aside redirect resolution on `GET /{code}` caching immutable JSON payload `CachedLink` under key `link:{code}`.
  - Expiration-bounded TTL calculation: cache TTL is strictly $\min(\text{configuredTTL}, \text{secondsUntilExpiry})$, ensuring cached entries never outlive link expiration.
  - Negative caching for unknown codes with short TTL (30s) to mitigate brute-force enumeration attacks.
  - Post-commit cache invalidation (`LinkCacheInvalidator`) using `@TransactionalEventListener(phase = TransactionPhase.AFTER_COMMIT)` triggered by `LinkInvalidatedEvent`:
    - Evicts key upon link status update (`PATCH /api/v1/urls/{id}`).
    - Evicts key upon soft-delete (`DELETE /api/v1/urls/{id}`).
    - Evicts key upon abuse takedown (`TakedownCli`).
    - Evicts key upon custom alias creation (`POST /api/v1/urls`) to ensure previous negative cache misses are immediately invalidated.
  - Safe fail-open outage policy: Redis connection/command exceptions log warnings and fall back seamlessly to PostgreSQL without failing redirect requests.
  - Micrometer cache metrics: counters `cache.hits`, `cache.misses`, and `cache.errors` registered with tag `cache=links`.
  - Scheduled Safe Browsing re-scan job (`SafeBrowsingRescanJob`) claiming active link batches via `SELECT ... FOR UPDATE SKIP LOCKED`, disabling flagged links with `ABUSE_TAKEDOWN`, and invalidating them from Redis.
  - Singleton Redis Testcontainer (`redis:7-alpine`) added to `AbstractIntegrationTest`.
  - Comprehensive integration test suite in `RedirectCacheIT` verifying cache hits, TTL bounds, negative caching, post-commit eviction, and container pause outage fail-open.
